# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Тренажёр слуха для музыканта: набор статических страниц без сборки, зависимостей и тестов. Рассчитан на работу «без рук» на iPhone (Safari, в том числе с домашнего экрана): проигрывает вопрос, даёт такт на раздумье, затем показывает и произносит ответ. Сейчас есть четыре тренировки — интервалы, виды аккордов (с обращениями), аккордовые прогрессии и ступени лада на фоне дрона.

## Команды

- Запуск: `open index.html` — страницы обязаны работать при открытии как `file://`, сервер не нужен.
- Перегенерация голосовых ответов: `./make-voice.sh <тренировка> [голос macOS]`, например `./make-voice.sh intervals` (также `chords`, `progressions`, `degrees`; голос по умолчанию `Samantha`, список — `say -v '?'`). Только macOS: использует `say` и `afconvert`.

Сборки, линтера и тестов нет.

## Архитектура

**Файлы.**

- `index.html` — меню со ссылками на тренировки; подключает `common.js` только ради регистрации service worker.
- `<тренировка>.html` (сейчас `intervals.html`, `chords.html`, `progressions.html` и `degrees.html`) — настройки одной тренировки (блок `.controls`) и inline-скрипт с её логикой.
- `assets/js/common.js` — общий движок (`window.EarTrainer`): звук, голос, цикл Start/Stop, темп, сохранение настроек.
- `assets/css/common.css` — общие стили меню и тренировок.
- `assets/voice/<тренировка>.js` — сгенерированный файл с голосом, вручную не правится.
- `sw.js` — service worker: офлайн-кеш для запуска с экрана «Домой» без сети.
- `manifest.webmanifest` — манифест веб-приложения, подключён на всех страницах. Его `scope` охватывает всю папку: без него iOS считает областью приложения только страницу, с которой добавлен ярлык, и остальные открывает во встроенном браузере с панелями сверху и снизу. iOS читает манифест при добавлении на экран «Домой», так что после его правки ярлык нужно добавить заново.

**Никаких ES-модулей и `fetch`.** Общий код подключается обычными `<script src>`, голос встроен как base64 — и то и другое потому, что `import` и `fetch` запрещены на `file://`.

**Контракт тренировки.** Страница вызывает `EarTrainer.create({ id, pickQuestion, play, describe })`:

- `id` — имя тренировки и префикс ключей `localStorage`;
- `pickQuestion()` — возвращает объект-вопрос произвольной формы;
- `play(q, t, beat, pass)` — планирует одно звучание вопроса с момента `t` через `EarTrainer.playNote(midi, time, dur, level = 1)`, `beat` — длительность доли в секундах; `pass = { replay, repeat }` — это повтор после ответа и номер звучания подряд (с 0); возвращает длину звучания в секундах. Для тянущихся звуков есть `EarTrainer.startTone(midi, time, level)` — тон звучит до вызова `stop(at)` у результата или до нажатия Stop;
- `describe(q)` — `{ label, answer, notes, voice }`: подпись в статусе, текст ответа, строка с нотами, фраза для голоса — ключ записи в `window.VOICE_DATA` (или массив фраз — записи прозвучат подряд). `label` виден уже во время вопроса и не должен выдавать ответ;
- `repeats` — необязательный: сколько раз подряд звучит вопрос по умолчанию;
- `phrases` — необязательный: все фразы, которые тренировка может произнести; при первом Start сверяются с файлом голоса, недостающие выводятся в `#diag`;
- `onStart()` — необязательный, вызывается при каждом нажатии Start.

`create` возвращает `persist(el, key)` (сохранение поля, списка или флажка; возвращает функцию чтения значения — числовые поля читаются только через неё, см. «Настройки») и `toggleGroup(container, items, key, onChange)` (сетка кнопок-переключателей, возвращает живой `Set` включённых id; элемент с `off: true` выключен по умолчанию; `onChange(enabled)` вызывается сразу и после каждого нажатия). В разметке страницы нужен только блок `.controls` с настройками самой тренировки. Остальное `create` достраивает сам (`buildPage`): перед `.controls` — ссылку в меню и экран с ответом (`#status`, `#answer`, `#notes`, `#diag`), в конце `.controls` — поля `#bpm`, `#repeats`, `#replay` и кнопки `#start`, `#stop`. Поэтому общие поля всегда идут после полей тренировки, а менять их нужно в `buildPage`, а не на страницах.

**Повторы вопроса.** Поле `#repeats` (1…8) задаёт, сколько раз подряд без пауз звучит вопрос; движок вызывает `play` нужное число раз, по одному вызову перед каждым звучанием (а не все повторы заранее). Значение по умолчанию — параметр `repeats` в `create` (если не задан — `DEFAULT_REPEATS`, 4): у интервалов, аккордов и прогрессий 4, у ступеней 1. Повтор после ответа (`#replay`) всегда звучит один раз. Порядок скриптов: `assets/voice/<тренировка>.js`, `assets/js/common.js`, inline-скрипт.

**Офлайн.** `sw.js` регистрируется из `common.js` и только при открытии по http(s); на `file://` его нет, и страницы обязаны работать без него. Стратегия — «сначала сеть»: при наличии сети всегда отдаётся свежая версия и обновляется кеш, кеш используется только без сети — поэтому версию кеша при выкладке менять не нужно. Запросы воркера идут с `cache: 'no-cache'`, мимо HTTP-кеша браузера (GitHub Pages разрешает держать файлы 10 минут, и без этого после выкладки приходили бы старые страницы); навигационный запрос при этом пересоздаётся по URL — у его копии Chrome `cache` не применяет. Список `FILES` в `sw.js` кешируется при установке, чтобы без сети работали и ни разу не открытые тренировки; если хоть одного файла из списка нет, установка не состоится.

**Теория и запись нот** — в `common.js`, общие для всех тренировок. `EarTrainer.KEYS` — 12 мажорных тональностей (индекс = высотный класс тоники; `letter` — индекс буквы тоники в `CDEFGAB`); `fillKeys(select)` строит из них список тональностей и должен вызываться до `persist`. Нота записывается буквой и знаком: букву определяет роль ноты (ступень, тон аккорда, интервал), знак — разница между высотой ноты и высотой буквы. `spell(letter, pc)` даёт название без октавы, `spellNotes(root, [{ midi, letters }])` записывает группу нот относительно основного тона (`letters` — на сколько букв нота отстоит от него, либо массив вариантов) и сам выбирает, писать основной тон на чёрной клавише с диезом или с бемолем, — как меньше знаков у всей группы, при равенстве как в `KEYS`. Октава в названии считается по букве (B♯3 звучит как C4). Запись строгая: дубль-диезы и дубль-бемоли пишутся везде, где их требует теория (B aug — B D♯ F♯♯, C dim7 — C E♭ G♭ B♭♭, ♭2 в D♭ — E♭♭), без упрощений до энгармонически равных нот. Таблицы букв лежат на страницах (у вида аккорда могут быть поправки — поле `letters`, так в dim7 задана уменьшённая септима): `LETTER_STEPS` в `intervals.html`, `STEP_LETTERS` в `chords.html`, поле `letter` в `DEGREES`. Также общие: `atOrAbove(pc, low)` — самая низкая нота высотного класса не ниже `low`, `randExcept(n, except)` — случайное число без повтора предыдущего, `pick(list)` — случайный элемент массива, `modeIs(value, option)` — выбран ли вариант в списке вида «A / B / Mixed» (при `mixed` — случайно, на каждом вопросе заново).

**Новая тренировка** — это: страница `<имя>.html` по образцу `intervals.html` (мета-теги и `<link rel="manifest">` в `<head>`, блок `.controls` со своими полями, три `<script>`), страница и файл с голосом в списке `FILES` в `sw.js`, ветка с фразами в `case` в `make-voice.sh`, сгенерированный `assets/voice/<имя>.js` и ссылка в `index.html`.

**Голос.** `window.VOICE_DATA` — объект `{ фраза: m4a/AAC в base64 }` (моно, 32 kbps — битрейт задан в `make-voice.sh`). Ключ — сама произносимая фраза, она же текст для `say` в `make-voice.sh`; страница находит запись по фразе, поэтому порядок записей не важен, но фразы на странице и в `make-voice.sh` должны совпадать буква в букву (без апострофов). Там, где фраза отличается от надписи на экране, она задана отдельно: поле `say` в `CHORDS` и `DEGREES`, массивы `INVERSION_SAY` и `SAY`. Записи декодируются через `decodeAudioData` при первом старте; если что-то не декодировалось или в файле нет фразы из `phrases`, причина выводится в `#diag`, а ответ остаётся только текстом. После правки фраз голос нужно перегенерировать.

**Интервалы: индекс = число полутонов.** Массивы `INTERVALS`, `SHORT_NAMES` и `LETTER_STEPS` в `intervals.html` индексируются числом полутонов 1…12. Названия из `INTERVALS` — они же фразы для голоса; при изменении набора или названий нужно поправить `names` в `make-voice.sh` и перегенерировать голос.

**Аккорды.** `CHORDS` в `chords.html` — виды аккордов с полутонами от основного тона (`steps`); `short` — подпись на кнопке и id вида в сохранённых настройках (менять его — значит сбросить у пользователя выбор этого вида); порядок в массиве — только порядок кнопок. Фраза для голоса — `say`, а если его нет — `name`; названия обращений — `INVERSION_SAY`. При добавлении вида нужно добавить его в `CHORDS`, его фразу — в `names` в `make-voice.sh` и перегенерировать голос; если у вида есть полутон, которого нет в `STEP_LETTERS`, его нужно добавить туда, иначе ноты не запишутся. Первые 12 видов (трезвучия и септаккорды) включены по умолчанию, остальные помечены `off`. У 11, maj7♯11, 13 и m13 часть ступеней пропущена. В обращении N басом становится N-я нота, а ноты ниже неё переносятся вверх на октаву (у аккордов шире октавы — на две); обращения выше третьего не используются (`MAX_INVERSION`). Виды с пометкой `rootOnly` (5, 6/9, add9, madd9, add11, 11) даются только в основном виде: у аккордов с добавленными или пропущенными тонами «N-я нота в басу» не соответствует принятым названиям обращений. Если выбранного обращения у аккорда нет (3-е у трезвучия, любое у `rootOnly`), берётся старшее доступное. Обращение произносится голосом только в режиме Random. В этом же режиме часть вопросов была бы на слух неразличима: sus2 и sus4, 6 и m7, m6 и m7♭5 — обращения друг друга, 7♭5 совпадает сам с собой через обращение, а у aug и dim7 одинаково звучат все обращения. Поэтому при случайном обращении аккорд с таким «двойником» даётся только в основном виде (`hasTwin`): таблица `SAME_SOUND` (строится из `CHORDS` при загрузке) находит расположения с теми же интервалами от баса, а двойником считается только включённый вид или сам аккорд — m7 теряет обращения, только пока включён 6. При заданном обращении ограничения нет: обращение известно, и ответ один. В режиме арпеджио ноты вступают снизу вверх через четверть (`ARPEGGIO_BEATS`) и держатся до конца; вопрос занимает такт, а арпеджио из пяти и более нот — два. Нижняя граница аккордов — `CHORD_LOW` (C3), а не `EarTrainer.LOW`: ниже тесное расположение звучит неразборчиво. Громкость каждой ноты делится на число нот (`NOTES_LEVEL / n`), иначе сумма клиппирует.

**Прогрессии.** В `progressions.html` аккорды — ступени мажорного лада (индексы 0…6 в `MAJOR_SCALE`, `QUALITY`, `NUMERALS`), только трезвучия maj/min/dim в основном виде, один аккорд на такт, размер 4/4. Вопрос — последовательность длиной `Bars` тактов (1…16); сколько раз подряд она звучит, задаёт поле `#repeats`. Голос называет номера ступеней подряд (фразы `SAY`: «One»…«Seven»). Источник: `COMMON` (коллекция общепринятых последовательностей; если готовой нужной длины нет, склеивается из более коротких), случайная генерация по весам `RANDOM_WEIGHTS` без повторов в соседних тактах, либо вперемешку. Флажок «Keep the same progression» держит одну последовательность (`kept`), пока не изменятся `Bars`/`Source` или не будет нажат Start (`onStart`); случайная тональность при этом меняется на каждом вопросе и не повторяется дважды подряд. Такт играется восьмыми: трезвучие, бас, и так четыре раза; бас — основной тон в октаве E2…D♯3, трезвучие — октавой выше. Названия аккордов (`chordName`) строятся по букве ступени, чтобы в бемольных тональностях были бемоли. Ответ и ноты выводятся строками по четыре такта (у страницы свой `<style>` с `white-space: pre-line`).

**Ступени.** В `degrees.html` на фоне дрона звучит нота, нужно назвать её ступень — одну из 12 хроматических (`DEGREES`, индекс = полутон от тоники; фраза для голоса — поле `say`). Дрон — тоника в двух соседних октавах (нижняя в E2…D♯3), запускается через `EarTrainer.startTone` и звучит непрерывно, пока идёт тренировка; при случайной тональности (поле `Key`, по умолчанию Random) она меняется через `QUESTIONS_PER_KEY` (8) вопросов — прежний дрон затухает, новый вступает; при выбранной тональности дрон не меняется, пока её не сменят в настройках. Первое звучание вопроса — такт одного дрона и такт с нотой; повторные звучания и повтор после ответа — только такт с нотой (для этого и нужен `pass`). При настройках по умолчанию (Repeats 1, Replay включён) цикл шесть тактов: дрон, нота, раздумье, ответ, повтор ноты, пауза; с выключенным Replay — первые четыре. Нота берётся в одной из двух октав над верхней тоникой дрона и не совпадает с ней. Состояние между вопросами (`key`, `asked`, `drone`, `droneKey`) сбрасывается в `onStart`, потому что Stop глушит и дрон.

**Звук** — Web Audio API: ноты синтезируются осциллятором с `PeriodicWave` (обертоны, чтобы низкие ноты были слышны), диапазон `EarTrainer.LOW`…`EarTrainer.HIGH` — MIDI 40–76 (E2–E5; выбран так, чтобы ноты можно было пропеть, к гитаре не привязан). Все источники текущего запуска идут через общий `runGain`, а сами узлы хранятся в `voices` — так «Stop» глушит всё разом.

**Цикл и отмена.** `loop()` в `common.js` — бесконечный async-цикл: вопрос (с повторами), такт на раздумье, голос, опциональный повтор, такт паузы. Его запускает `run()` (обработчик Start) внутри `try/catch`: при любой ошибке — сбой звука, исключение в `pickQuestion`/`play`/`describe` — тренировка останавливается через `stop()`, а в `#status` выводится `Error: …`. Звучания вопроса планируются по одному (`playOnce`), а не все повторы разом: иначе длинный вопрос (16 тактов × 8 повторов — 2048 нот) создавал бы тысячи узлов Web Audio заранее, а настройки не действовали бы до следующего вопроса. Фазы идут по сетке на аудиочасах: переменная `at` хранит момент начала очередной фазы, звук планируется ровно на него, а цикл ждёт через `waitUntil(at, my)` — пока `ctx.currentTime` не подойдёт к этому моменту (с запасом `LOOKAHEAD`, 0,15 с; пока страница скрыта — `HIDDEN_LOOKAHEAD`, 1,3 с: на заблокированном экране таймеры опаздывают до секунды, и с обычным запасом между повторами вопроса появлялись бы паузы). Голым `sleep` в цикле ждать нельзя: если iOS приостановит контекст, аудиочасы встанут, а цикл на таймерах уйдёт вперёд и запланирует всё в одну точку. Если таймер проснулся с опозданием, `notBefore` сдвигает фазу, чтобы не планировать в прошлое. Отмена сделана через счётчик `runId`: `run()` и `stop()` его инкрементируют, а цикл после каждого `await` сверяет `my !== runId`. Любой новый `await` в цикле должен сопровождаться такой проверкой.

**Тайминг в долях, а не в секундах.** Длительности заданы константами в долях: такт — `EarTrainer.BAR_BEATS`, единственное место, где задан размер 4/4; константы страниц (`WHOLE_BEATS`, `HALF_BEATS`, `BAR_BEATS`) выводятся из него и переводятся в секунды через `beatSec()`, который каждый раз читает текущий темп. Смена Tempo и Repeats действует с ближайшего звучания вопроса или паузы: уже запланированное звучание (один вызов `play` — у прогрессий это все такты последовательности) доигрывает в прежнем темпе.

**Настройки** сохраняются в `localStorage` под ключами `ear-trainer.<id>.<ключ>` — у каждой тренировки свои, включая темп и повтор; каждое обращение обёрнуто в `try/catch`, так как хранилище может быть недоступно. Числовые поля `persist` приводит к целому в пределах `min`…`max` (пустое — к значению по умолчанию) при загрузке и при каждом изменении, так что на экране стоит то же число, с которым работает тренировка. Читать их нужно через функцию, которую вернул `persist` (`bpm()`, `repeatCount()`, `barCount()`), а не через `el.value`: она отдаёт последнее завершённое значение, а не набранное наполовину («1» на пути от «80» к «120»). Чтобы набранное, но не подтверждённое значение не осталось на экране без действия, `run()` при нажатии Start снимает фокус с активного поля — оно получает `change`. Границы и значения по умолчанию заданы атрибутами `min`, `max`, `value` в разметке.

**Особенности iOS**, которые нельзя ломать: `navigator.audioSession.type = 'playback'` (звук при включённом беззвучном режиме), создание/`resume()` `AudioContext` только по жесту пользователя, возобновление контекста на `visibilitychange` и при событии `statechange` (если iOS прервала контекст во время тренировки), отступы через `env(safe-area-inset-*)` (при запуске с экрана «Домой» страница из-за `apple-mobile-web-app-status-bar-style: black-translucent` заходит под статус-бар, и верхний отступ обязателен).

**Звук на заблокированном экране ненадёжен.** iOS может остановить Web Audio при блокировке экрана или уходе Safari в фон; подтверждённого способа это предотвратить нет, поведение меняется от версии к версии. По проверке на iPhone автора (13.11.2026): во вкладке Safari звук при блокировке пропадает, а при запуске с экрана «Домой» продолжает играть — поэтому штатный способ запуска именно такой.
